# Yuki Reader 设计文档（MVP）

日期：2026-08-11
状态：待用户审阅

## 1. 目标与定位

Yuki Reader 是一个类似 MojiRead 的日语阅读 Web 应用：支持上传 txt 文本、按句阅读、点词查词典、点句或拖选调用 LLM 翻译。

- MVP 只面向电脑端（手机端不做）。
- 定位：个人日常使用 + 作品集展示。内置一本公有领域示例书，访客打开即可体验，无需上传文件。
- 运营成本趋近于零：文本解析与分词在浏览器端完成，词典自托管，翻译请求使用用户自带 API Key（BYOK）。

## 2. 范围

### MVP 包含

- 上传本地 txt，自动识别 UTF-8 / Shift-JIS / UTF-16 编码并解析成阅读页。
- 内置示例书《こころ》（夏目漱石，青空文库公有领域文本）。
- 点词查词典：读音、词性、英文释义，附"中文释义"按钮（调 LLM 翻译当前词条释义）。
- 点句 / 拖选调用 LLM 翻译，结果展示在右侧固定侧栏。
- 右侧侧栏只显示"当前结果"：新操作直接替换旧结果，不保留历史。
- 阅读设置：字号（小/中/大）、行距（紧凑/标准/宽松）、主题（浅色/深色/米黄纸张）。
- 阅读进度：按章节位置保存到 localStorage，重新打开回到上次位置。
- BYOK 设置：提供商预设 + 自定义 Base URL/模型名，API Key 仅存浏览器 localStorage。
- 部署：Spring Boot fat jar（含前端构建产物），VPS 单进程运行。

### MVP 明确不做

- 手机端适配与触摸交互。
- 翻译缓存（本地或服务端均不做）。
- 服务端分词（MeCab / Sudachi）。
- 竖排排版。
- 账号体系、多人使用、云同步。
- 预计算中文释义词库（后续可做）。
- 生词本、收藏、标注。

## 3. 架构

采用"方案 A：React 前端 + 极薄 Java 后端"：

| 组件 | 职责 |
| --- | --- |
| 前端 React（Vite） | 阅读器界面、txt 解析、kuromoji.js 分词、点词/点句/拖选交互、设置面板 |
| 后端 Spring Boot 3（Java 17） | 提供两个 API、托管前端静态资源、访问 SQLite |
| SQLite | 存 JMDict 词条，部署时一次性导入（CC BY-SA 4.0，页面署名） |
| 外部 LLM API | 任意 OpenAI 兼容接口（DeepSeek / Kimi / GLM / OpenAI / OpenRouter / 自定义地址），key 由用户提供 |

### 数据流

```
上传 txt / 打开内置书
  → 浏览器检测编码
  → 分段落、分句
  → kuromoji 分词，每句得到 token 数组（表面词/读音/词性/词典原形）
  → 按"句子容器 + 词 span"渲染阅读页

点词      → GET /api/dict?word=词典原形 → 侧栏词典卡
点句/拖选 → POST /api/chat             → 侧栏翻译卡
```

## 4. 接口设计

### GET /api/dict?word=<词典原形>

返回匹配词条列表，每项包含：表面词、读音、词性、英文释义。未命中返回空列表。

### POST /api/chat

请求体：`{ baseUrl, model, apiKey, messages }`。

- 后端仅做转发，调用 OpenAI 兼容的 `/chat/completions` 接口。
- apiKey 不落库、不打日志；生产日志对请求体脱敏。
- 上游超时、限流、鉴权错误转换为可读的错误信息返回给前端。

## 5. 正文解析与渲染

- 编码检测顺序：BOM 优先 → UTF-8 严格解码 → Shift-JIS（cp932）→ UTF-16。
- 段落按空行切分；句子按日文句末标点（。！？…及闭括号）切分。
- 分词使用 kuromoji.js；每个 token 记录表面词、读音、词性、词典原形（如"呼んで"的原形为"呼ぶ"）。
- 渲染结构：`句子容器 > 词 span`。词 span 悬停时浅色高亮，提示可点击。

## 6. 交互与"词/句"判定

判定不依赖对文本内容的猜测，而是依赖渲染后的 DOM 结构：

- 单击落在某个词 span 上 → 判定为词，用该 token 的词典原形查 `/api/dict`，结果进侧栏词典卡。词的事件处理器阻止冒泡，避免同时触发整句翻译。
- 单击落在句子容器的非词区域（词间隙、行尾空白）→ 判定为整句，将整句文本发给 `/api/chat`。
- 拖选：鼠标松开时检查浏览器选区。
  - 无选区 → 忽略。
  - 选区恰好等于单个词 span 的内容（如双击选中一个词）→ 按词处理，走词典。
  - 选区跨多个词 → 按短语/句子处理，走 LLM 翻译选区。
- 词典未命中时：词典卡显示读音和"未找到释义"，并提供"用 LLM 解释这个词"按钮作为降级路径，不误判为句子翻译。

## 7. 侧栏（布局 B，无历史）

- 侧栏固定于右侧，只有一块结果区。
- 点词 → 词典卡：表面词、读音、词性、英文释义、"中文释义"按钮。
  - "中文释义"点击后调 LLM 翻译当前词条释义，展示加载状态；失败可重试。
- 点句/拖选 → 翻译卡：原文、译文、"复制"、"重试"。
- 新操作替换旧结果；点击正文其他位置或按 Esc 只取消选区高亮，侧栏内容保留。

## 8. 阅读设置与进度

- 字号：小 / 中 / 大；行距：紧凑 / 标准 / 宽松；主题：浅色 / 深色 / 米黄纸张。
- 排版固定横排（MVP 不做竖排）。
- 阅读进度按"章节 + 滚动百分比"保存到 localStorage。

## 9. BYOK 设置

- 提供商预设：DeepSeek、Kimi、GLM、OpenAI、OpenRouter；另提供"自定义 Base URL + 模型名"。
- 字段：Base URL、模型名、API Key；提供"测试连接"按钮。
- Key 只存在浏览器 localStorage；请求经后端 `/api/chat` 转发，后端不持久化。
- 未配置 Key 时，点击翻译或中文释义引导用户前往设置页。

## 10. 存储与内置书

- 用户上传的书存浏览器 IndexedDB。
- 《こころ》随前端静态资源打包，打开即读；访客无需上传即可体验。
- 春物等个人版权书籍只通过"上传"入口本地使用，不进入公开包。
- 分词结果保存在会话内存中，翻页不重复计算；MVP 不做持久化。

## 11. 版权

- JMDict：CC BY-SA 4.0 许可，页面页脚署名。
- 《こころ》：青空文库公有领域文本。
- 不打包任何商业出版物全文。

## 12. 错误处理

| 场景 | 处理 |
| --- | --- |
| LLM 超时 / 限流 | 侧栏显示错误信息 + 重试按钮 |
| 401（key 无效） | 明确提示"API Key 无效，请检查设置" |
| 429（额度不足） | 明确提示"额度不足或限流，请稍后重试" |
| 词典未命中 | 显示读音 + "未找到释义" + "用 LLM 解释这个词"按钮 |
| 编码无法识别 | 上传页给出提示，建议另存为 UTF-8 |

## 13. 部署

- 前端 `npm run build` 产物复制到 Spring Boot 的 `src/main/resources/static`。
- Maven 打包为单个 fat jar；VPS 单进程运行，建议 1–2GB 内存。
- 首次启动执行一次性初始化：导入 JMDict 到 SQLite、校验内置书资源。

## 14. 测试

- 单元测试：编码检测、分句规则、分词结果包装。
- 集成测试：`/api/dict`、`/api/chat`（含错误映射）。
- 前端组件冒烟测试（从简，覆盖阅读页渲染与侧栏状态切换）。

## 15. 后续可扩展（不在 MVP）

- 翻译缓存与预计算中文释义（进一步降低成本与延迟）。
- 竖排排版、手机端适配。
- 服务端分词（为多人场景做准备）。
- 账号体系、书库云同步、生词本。
